# IndexNow: автоматичне сповіщення пошуковиків про нові сторінки

Опис механізму, який працює на `ridna.net`. Самодостатній — за ним можна
підняти те саме на іншому проєкті з нуля.

## Що це

IndexNow — відкритий протокол, яким сайт сам повідомляє пошуковики, що
сторінка зʼявилась або змінилась. Замість чекати, поки краулер зайде сам,
ви надсилаєте йому список URL.

**Хто підтримує:** Microsoft Bing, Yandex, Seznam, Naver. Один запит
сповіщає всіх одразу — вони обмінюються даними між собою.

**Хто НЕ підтримує: Google.** Він тестував протокол і не впровадив. Його
власний Indexing API офіційно обслуговує лише сторінки типів `JobPosting`
і `BroadcastEvent` — для звичайних статей його використання суперечить
документації, і такі запити ігноруються. Для Google лишаються тільки два
механізми: **sitemap із правильним `lastmod`** і ручний «Запит на
індексування» у Search Console (квота ~10 URL на добу).

Тобто IndexNow не замінює sitemap, а доповнює його з боку Bing.

## Як це влаштовано

Три складники:

1. **Ключ** — довільний рядок із 8–128 символів (`a-z`, `A-Z`, `0-9`, `-`).
   Генерується один раз і більше не змінюється.
2. **Файл ключа** — лежить у корені сайту за адресою `https://<домен>/<ключ>.txt`
   і містить **рівно цей ключ** без пробілів і переносів. Це доказ, що ви
   володієте доменом.
3. **Запит** — POST з JSON-тілом на `https://api.indexnow.org/indexnow`.

### Генерація ключа

```bash
node -e "console.log(require('crypto').randomBytes(16).toString('hex'))"
```

Отриманий рядок зберігаємо у файл із такою ж назвою:

```bash
KEY=<ключ>
printf '%s' "$KEY" > "$KEY.txt"
```

`printf` без `\n` — важливо: деякі реалізації звіряють вміст байт у байт.

### Формат запиту

```http
POST https://api.indexnow.org/indexnow
Content-Type: application/json; charset=utf-8

{
  "host": "ridna.net",
  "key": "<ключ>",
  "keyLocation": "https://ridna.net/<ключ>.txt",
  "urlList": [
    "https://ridna.net/blog/stattya-odyn/",
    "https://ridna.net/blog/stattya-dva/"
  ]
}
```

**Відповіді:** `200` або `202` — прийнято. `400` — неправильний формат,
`403` — ключ не підтверджено (файл недоступний або вміст не збігається),
`422` — URL не належать вказаному хосту, `429` — забагато запитів.

Ліміт — до 10 000 URL за один запит.

## Реалізація в цьому проєкті

Команда в `tools/blog.mjs`:

```bash
node tools/blog.mjs indexnow <slug> [<slug>...]   # конкретні статті
node tools/blog.mjs indexnow --all                # усе опубліковане
```

Що вона робить, окрім самого запиту:

- **Перевіряє живий файл ключа.** Качає `https://<домен>/<ключ>.txt` і
  звіряє вміст. Якщо файл ще не задеплоєний — зупиняється з поясненням,
  а не надсилає запит, який мовчки відкинуть.
- **Відмовляється надсилати чернетки.** Статті під `<meta name="robots"
  content="noindex">` до списку не потрапляють: інакше краулер прийде на
  сторінку, яку ми самі закрили від індексації.
- **Додає `/blog/`** до списку, бо лістинг теж змінився.

## Правила використання

**Запускати тільки після `git push` і завершення деплою.** На GitHub Pages
між пушем і оновленням живої сторінки проходить до кількох хвилин. Пінг,
надісланий раніше, приводить краулер на стару версію — і наступного разу
він прийде нескоро.

**Не надсилати те, що не змінилось.** Протокол розрахований на сповіщення
про зміни. `--all` доречний при першому підключенні або після масової
правки; у звичайному режимі — лише слаг нової статті.

**Не плутати з sitemap.** Sitemap лишається основним механізмом і єдиним,
що працює для Google. IndexNow його не замінює.

## Як підняти на іншому проєкті

1. Згенерувати ключ і покласти `<ключ>.txt` у корінь сайту.
2. Задеплоїти й переконатись, що файл віддається з `200` і правильним вмістом.
3. Надіслати POST за форматом вище — будь-чим: `curl`, скрипт складання,
   CI-крок після деплою.
4. Переконатись, що в список не потрапляють сторінки з `noindex`,
   чернетки, службові й закриті в `robots.txt` адреси.

Мінімальний варіант без коду:

```bash
curl -X POST https://api.indexnow.org/indexnow \
  -H 'Content-Type: application/json; charset=utf-8' \
  -d '{"host":"example.com","key":"<ключ>","keyLocation":"https://example.com/<ключ>.txt","urlList":["https://example.com/storinka/"]}'
```

## Що залишається робити руками

Для **Google** автоматизації немає. Працює тільки sitemap із `lastmod`,
який має оновлюватись при кожній зміні сторінки, і за потреби — ручний
запит на індексування в Search Console для свіжих матеріалів.
