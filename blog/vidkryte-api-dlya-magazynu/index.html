Відкрите API: як підключити CRM до сайту, маркетплейсу чи обліку

3 листопада 2026 р. · Ridna

Коротко

Відкрите API — це спосіб підключити CRM до будь-якого сервісу: власного сайту, маркетплейсу, програми обліку, чат-бота чи навіть таблиці. Замовлення звідусіль лягають в одне місце, з ТТН в один тап і спільними залишками.

Це робота для розробника або для no-code-звʼязки через Make, Zapier чи ApiX-Drive. Самій писати код не потрібно — достатньо переслати документацію тому, хто цим займається.

API Ridna вміє три речі: приймати замовлення звідки завгодно, синхронізувати каталог і залишки та записувати оплати, віддаючи статус замовлення й номер ТТН.

Адреса — https://api.ridna.net/v1, автентифікація ключем, ліміт 120 запитів за хвилину. Потрібен тариф Pro або пробний період; ключ видає підтримка.

Коли API справді потрібне

Перш ніж братися за код, варто перевірити, чи задача не вирішується простіше. Для магазину є три різні шляхи, і плутати їх дорого.

Ознака, що вам потрібне саме API: дані мають ходити в обидва боки. Не просто «замовлення прийшло», а ще й «залишок списався», «ціна оновилась», «статус поїхав назад на сайт».

Що вміє API Ridna

Три групи операцій:

  • Приймає замовлення звідки завгодно — із власного сайту, маркетплейсу, лендингу чи чат-бота. Покупця знаходить за телефоном або ніком Instagram, тож дублі не плодяться.
  • Веде каталог і залишки — створює й оновлює товари з варіантами, знижками й фото, читає наявність, змінює ціну та залишок.
  • Записує оплати й віддає назад статус замовлення та номер ТТН.

Важлива деталь: замовлення з API приходить так само, як із вітрини. Адреса Нової Пошти чи Укрпошти передається одразу з кодами відділень, тож накладна створюється одним тапом, без ручного введення. Залишок списується, а власниці приходить push.

Що можна підключити

Найчастіші сценарії: маркетплейси Rozetka і Prom, програми обліку на кшталт BAS чи Dilovod, Google Таблиці, чат-боти, власний сайт, інші CRM.

Окремо варто сказати про no-code: Make, Zapier і ApiX-Drive дозволяють зібрати звʼязку без програміста. Це реалістичний шлях для магазину, у якого немає розробника, але є людина, готова розібратись у конструкторі сценаріїв.

Що знати до початку

Технічні рамки, які варто передати розробнику разом із посиланням на документацію:

  • Адреса: https://api.ridna.net/v1. Версія v1 — адреси не змінюватимуться так, щоб зламати інтеграцію; у відповідях можуть зʼявлятись нові поля, незнайомі просто ігноруються.
  • Автентифікація: заголовок Authorization: Bearer з ключем.
  • Ліміт: 120 запитів за хвилину на ключ. Понад це — відповідь 429 із заголовком Retry-After.
  • Тариф: Pro або пробний період. Без нього API відповідає 403 plan_required, а власниця отримує сповіщення, що замовлення з сайту не створено.
  • Формат: JSON у UTF-8, суми в гривнях, дати в ISO 8601 за UTC.

Документація з прикладами, описом помилок і /llms.txt для ШІ-помічника — на api.ridna.net.

Ключ — це пароль

Найчастіша помилка в таких інтеграціях — покласти ключ туди, де його видно.

Запити мають іти із сервера сайту, а не з браузера: ключ, вставлений у JavaScript сторінки, побачить будь-хто, хто відкриє вихідний код. Так само його не варто класти в репозиторій.

Якщо ключ усе ж засвітився — напишіть у підтримку, його відкличуть і видадуть новий. Це займає хвилини, на відміну від розбору наслідків.

Як отримати ключ

Потрібен тариф Pro або пробний період. Ключ видає підтримка: напишіть у Telegram @ridna_crm і вкажіть, з якого акаунта Ridna ви звертаєтесь. Ключ показується один раз — його варто зберегти одразу.

Кому це не потрібно

Якщо ваші замовлення приходять із Direct і з вітрини, а сайту на сторонній платформі немає — API вам не знадобиться. Воно не додає можливостей усередині застосунку, а лише відкриває двері для зовнішніх систем.

Сенс зʼявляється там, де є друга система, яка має знати те саме, що й CRM: склад, маркетплейс або бухгалтерія. Поки такої системи немає, немає й задачі.

Часті питання

Що дає відкрите API Ridna?

Три групи можливостей: приймати замовлення з будь-якого джерела — сайту, маркетплейсу, лендингу чи чат-бота; синхронізувати каталог і залишки, створюючи та оновлюючи товари; записувати оплати й віддавати статус замовлення та номер ТТН. Замовлення з API приходить так само, як із вітрини, а адреса передається з кодами відділень, тож ТТН створюється одним тапом.

Чи треба вміти програмувати, щоб підключити API?

Ні. Це робота для розробника, якому достатньо переслати документацію з api.ridna.net. Є й no-code-шлях — через сервіси Make, Zapier або ApiX-Drive, які дозволяють зібрати звʼязку без написання коду.

Які обмеження в API Ridna?

Ліміт — 120 запитів за хвилину на один ключ; при перевищенні повертається 429 із заголовком Retry-After. Потрібен тариф Pro або пробний період: без нього API відповідає 403 plan_required. Версія v1, адреси не змінюватимуться так, щоб зламати наявну інтеграцію.

Як отримати ключ до API?

Ключ видає підтримка: напишіть у Telegram @ridna_crm і вкажіть, з якого акаунта Ridna ви звертаєтесь. Потрібен тариф Pro або пробний період. Ключ показується один раз, тож його варто зберегти одразу й тримати лише на сервері.

Коли замовлення приходять звідусіль

Маркетплейс, свій сайт і програма обліку зазвичай живуть окремо від CRM — і зводити дані доводиться руками.
